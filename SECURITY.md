# Security Policy

## Supported Versions

We currently provide security updates for the following versions of Scrutium:

| Version | Supported |
| ------- | --------- |
| Latest release | :white_check_mark: |
| Older releases | :x: |

Security fixes are generally applied to the latest supported release. Users are encouraged to keep their deployment up to date.

## Reporting a Vulnerability

If you believe you have discovered a security vulnerability in Scrutium, please report it privately rather than opening a public GitHub issue.

Please include:

- A clear description of the vulnerability
- Steps required to reproduce it
- The potential impact
- Any relevant screenshots, logs, or proof-of-concept code
- Your suggested remediation, if applicable

### Responsible Disclosure

We ask security researchers to give us a reasonable opportunity to investigate and address a reported vulnerability before publicly disclosing it.

After receiving a report, we will:

1. Review the report and assess its validity and severity.
2. Acknowledge receipt as soon as reasonably possible.
3. Investigate and, where appropriate, work on a fix.
4. Provide updates as the investigation progresses.
5. Release or deploy a security fix when appropriate.

If a report is determined not to represent a security vulnerability, we will provide an explanation where appropriate.

### Do Not Publicly Disclose

Please do not publicly disclose vulnerabilities, exploit details, credentials, authentication bypasses, or other sensitive security information before we have had an opportunity to investigate.

Thank you for helping us keep Scrutium and its users secure.
